# Fourgetu 3x-ui Upstream v3.8.5 Sync Design

## Goal

将 Fourgetu 分支从 `v3.7.0-fourgetu.4` 同步到官方 `MHSanaei/3x-ui v3.8.5`，完整保留当前分支的所有独有功能；如果官方已实现同一功能，则以官方实现为准，并对已有数据和调用方做兼容迁移。

## Baseline and upstream

- Current fork baseline: `Fourgetu/3x-ui` `main` at `v3.7.0-fourgetu.4` (`58120805`).
- Upstream target: `MHSanaei/3x-ui` tag `v3.8.5` (`7ef22f94`).
- Common ancestor: official `v3.7.0` (`f727d04f`).
- Official `v3.8.5` requires Go 1.27.1 and bundles Xray-core v26.9.9.
- The current development environment has Node 24 but does not have Go, a C compiler, or GNU Make; Go verification must therefore run in CI or a Go-enabled Linux/Windows environment.

## Fourgetu feature inventory to preserve

### User-level bandwidth limits

Keep the identity-bound, per-client/per-inbound upload and download limits expressed in Mbps. Preserve the database model and migration, API endpoints, client form/list UI, subscription annotations, dedicated Xray loopback routing, GOST forwarding, runtime reconciliation/recovery, dynamic limit updates, cleanup on client/inbound deletion, and per-GOST-service limiter scoping.

The relevant existing units are `internal/database/model/client_speed_limit.go`, `internal/userspeed/`, `internal/sub/speed_limit.go`, `internal/web/service/client_speed_limit.go`, the Xray service integration, client controllers, client pages, translations, and their tests.

### Inbound templates and relay workflow

Preserve the recommended VLESS Reality Vision, VLESS Reality gRPC, Trojan TLS, VMess WebSocket TLS, and Hysteria2 templates; certificate-aware bulk creation; automatic reuse of subscription IDs, certificates, and Reality keys; manual-mode fallback; the relay wizard; direct share-link parsing for VLESS, VMess, Trojan, Shadowsocks, SOCKS, and HTTP; entry-to-landing routing; connectivity testing; inbound relay labels; and reuse of an existing inbound.

The main units are `frontend/src/lib/xray/inbound-presets.ts`, `frontend/src/lib/xray/relay.ts`, `frontend/src/pages/inbounds/RelayWizardModal.tsx`, the inbound form/list pages, `internal/web/service/inbound.go`, and related controller/API/schema/test files.

### Multi-server and client administration

Preserve remote-server selection during inbound creation, remote deployment for templates and relay workflows, offline-node display and selection blocking, client source classification/filtering, bulk inbound/client cleanup, per-inbound and per-client QR generation, QR titles, server/inbound/client/port node labels, duplicate-name suffixing, subscription identity/remark behavior, external links, and portable import/export compatibility.

### Chinese distribution and documentation

Preserve the Chinese README feature inventory and the integration with `Fourgetu/3x-ui-cn-installer`. Update version references and installation/update URLs so a stable install or update resolves Fourgetu releases and does not silently download `MHSanaei/3x-ui` binaries.

## Integration strategy

1. Merge official tag `v3.8.5` into an isolated synchronization branch based on the current fork `main`.
2. For each overlapping file, first accept the official `v3.8.5` structure, then reapply only the Fourgetu behavior that is not present upstream. This prevents carrying obsolete upstream code around a large refactor.
3. Treat equivalent behavior as an official-wins conflict. Equivalence requires matching user-visible behavior, API/data contract, runtime semantics, and migration behavior; a similarly named field or generic rate limiter is not sufficient.
4. Keep the Fourgetu speed-limit model only if the official source still lacks identity-bound per-client upload/download shaping. If the official source adds it, map the existing table and API data into the official contract, retain backward-compatible reads where necessary, and delete duplicate runtime paths.
5. Preserve the module path `github.com/mhsanaei/3x-ui/v3` and the upstream dependency/toolchain updates unless a custom feature cannot compile against them. Resolve generated frontend artifacts only through the repository generators.
6. Update `README.md`, `install.sh`, `update.sh`, release workflow references, and the Chinese installer integration together. The default path must fetch the latest stable Fourgetu release; an explicit tag path must install the requested Fourgetu tag.

## Data and compatibility rules

- No uninstall/reinstall migration is allowed as part of the code change.
- Existing SQLite and PostgreSQL databases must open without losing clients, inbounds, nodes, relay metadata, external links, subscription identity settings, or speed-limit rows.
- Any model or schema change must be included in `internal/database/db.go`/`migrate_data.go`, then reflected through generated OpenAPI/Zod/TypeScript output.
- State-changing inbound/client operations must continue through `internal/web/runtime/` so master/sub-node deployments remain correct.
- Existing unlimited clients must retain the original no-limiter path.
- Unsupported protocols/transports must remain explicit in the API/UI rather than receiving a partially applied limit.

## Verification design

### Backend

- Run `go test -shuffle=on -count=1 ./...` and `go test -race -shuffle=on -count=1 ./...` in a Go 1.27.1 environment.
- Run focused tests for `internal/userspeed`, `internal/database`, `internal/sub`, `internal/web/service`, `internal/web`, and `internal/xray`.
- Verify SQLite migration and the available PostgreSQL schema tests.
- Run `go vet ./...` and `golangci-lint run`.

### Frontend and generated contracts

- Run `cd frontend && npm ci`.
- Run `npm run gen`, then confirm generated files are clean.
- Run `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run test`, `npm run build`, and `npm run build-storybook`.
- Recheck link-generation and subscription fixtures after upstream subscription-page and protocol changes.

### Distribution

- Run shell syntax checks for `install.sh` and `update.sh`.
- Verify the release workflow still builds all supported architectures and packages the correct Xray/MTProto assets.
- Verify version output and the generated release asset naming for the new Fourgetu `3.8.5` release.
- Verify installer resolution points at `Fourgetu/3x-ui/releases/latest` and that `x-ui update` cannot fall back to `MHSanaei/3x-ui`.

## Out of scope

- New features unrelated to upstream compatibility or the listed Fourgetu feature inventory.
- Changing protocol semantics or the public API solely for stylistic consistency.
- Pushing or publishing a release to GitHub before the local/CI verification is complete.
