# Fourgetu 3x-ui Upstream v3.8.5 Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Merge official \`MHSanaei/3x-ui v3.8.5\` into Fourgetu \`v3.7.0-fourgetu.4\` while preserving every Fourgetu-only feature and using official behavior whenever the same feature exists upstream.

**Architecture:** Start from the official \`v3.8.5\` tree, retain Fourgetu-only files, and reapply custom behavior at the new upstream integration points. Keep user-speed limits as a separate identity-bound runtime only when the official source has no equivalent; otherwise migrate to the official contract and remove duplicate paths. Keep the fork's distribution scripts pointed at Fourgetu releases.

**Tech Stack:** Go 1.27.1, Gin, GORM, SQLite/PostgreSQL, Xray-core v26.9.9, React 19, Ant Design 6, TypeScript, Vite 8, Vitest, npm, shell scripts, GitHub Actions.

**Spec:** \`docs/superpowers/specs/2026-09-16-upstream-v3.8.5-sync-design.md\`

## Global Constraints

- Preserve every feature listed in \`docs/superpowers/specs/2026-09-16-upstream-v3.8.5-sync-design.md\`.
- If official v3.8.5 has equivalent user-visible behavior, API/data contract, runtime semantics, and migration behavior, official code wins.
- Existing SQLite and PostgreSQL data must survive; no uninstall/reinstall migration is allowed.
- All state-changing inbound/client operations must continue through \`internal/web/runtime/\`.
- Do not hand-edit \`frontend/src/generated/\` or \`internal/web/dist/\`; regenerate them.
- New or changed API routes must stay synchronized with \`frontend/src/pages/api-docs/endpoints.ts\` and the generated OpenAPI artifacts.
- Every new English translation key must exist in all locale JSON files and be referenced by frontend or Go code.
- Release artifacts must target Fourgetu/3x-ui, not MHSanaei/3x-ui.
- The current workstation has Node 24 but no Go 1.27.1, C compiler, or GNU Make; Go tests and release builds require CI or a Go-enabled environment.
